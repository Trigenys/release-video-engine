# Concierge Pilot — Issue #7

## Objective

Validate the commercial outcome before adding more self-serve platform surface.

For each qualified prospect, Release Video Engine should turn one recent public release into a branded short-video artifact or tailored preview, then use that artifact in personalized outreach.

## Offers under test

1. **Launch Pack** — one release transformed into publish-ready video assets.
2. **Monthly Release Automation** — recurring release-to-video delivery for teams that ship frequently.
3. **Brand Template Setup** — one-time setup for a reusable branded video system.

Pilot price anchors are defined in `docs/validation-offers-and-outreach.md`. They are validation instruments, not final product pricing.

## Pilot success criteria

- 20 personalized outreaches sent with a real artifact or tailored preview.
- Replies and objections tracked.
- At least 3 pricing conversations initiated.
- Time spent per video measured.
- At least 1 prospect reaches a paid-pilot or explicit procurement step.
- If not, revise ICP, offer or positioning before additional platform expansion.

## Artifact rule

A prospect only counts as outreach-ready when there is something concrete to show.

Preferred evidence order:

1. real short render from the prospect's public release;
2. branded still / storyboard from the same release when a full render is not yet justified;
3. tailored mock only when clearly labeled as a preview.

Do not fabricate testimonials, customer relationships, performance metrics, private screenshots or product claims.

## Outreach structure

Keep outreach short:

1. mention the exact release;
2. show the artifact;
3. explain the outcome in plain language;
4. ask one buying question.

Do not lead with implementation details, Remotion, HyperFrames or rendering architecture. The prospect is buying faster release marketing, not our renderer.

## Time and unit-economics capture

For every generated artifact record:

- research / release-normalization time;
- brand-asset preparation time;
- template adjustment time;
- render time;
- QA time;
- total operator time;
- compute / external API cost where measurable.

This feeds issue #8.

## Relationship with issue #1

Issue #7 is the execution layer for the commercial validation in #1.

The same outreach should therefore capture:

- current release-communication workflow;
- release frequency;
- current video/content pain;
- who owns release marketing;
- willingness to pay;
- preferred buying model;
- objections.

Avoid running two disconnected research motions against the same prospects.
